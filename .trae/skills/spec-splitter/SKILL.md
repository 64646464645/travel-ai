# 需求拆分（Spec Splitter）

本技能用于把用户的需求拆分、结构化，并写入 `.trae/spec` 目录。每次执行都会创建一个以日期与主题命名的子目录，并在其中生成三个文档：`spec.md`（需求规格）、`tasks.md`（任务拆分）、`checklist.md`（检查清单）。

## 执行流程

1. **确定主题与目录名**
   - 从用户需求中提炼一个简短的英文 slug（小写、用 `-` 连接），例如 `monorepo`、`user-auth`。
   - 使用当前日期，目录命名格式为 `<YYYY-M-D>-<slug>`（月份、日期不补零），例如 `2026-8-20-monorepo`。
   - 目标目录：`travel-ai/.trae/spec/<YYYY-M-D>-<slug>/`。
   - 如果同名目录已存在，则在 slug 后追加数字后缀（如 `-2`）避免覆盖。

2. **拆分需求**
   - 先向用户澄清关键信息（目标、边界、验收标准）后再落盘；若用户已给出足够信息则直接生成。
   - 将需求拆成清晰、可执行、可验证的条目，粒度适中，避免过度拆分。

3. **生成三个文档**（模板见下），用需求内容填充。

4. **汇报**：说明生成的文件路径与拆分结果概要。

## 文档模板

### spec.md

```markdown
# <需求标题>

> 状态：草案（待评审）
> 日期：<YYYY-MM-DD>
> 目标仓库：`travel-ai/`

## 1. 背景与目标

<说明为什么做这件事，以及要达成的目标>

## 2. 非目标

- <明确不做的事情，避免范围蔓延>

## 3. 需求描述

### 用户故事 / 使用场景

- <从使用者视角描述>

### 功能需求

- <可验证的功能点，逐条列出>

## 4. 验收标准

- [ ] <可验证的完成标准，尽量可测试>
```

### tasks.md

```markdown
# <需求标题> - 任务拆分

## 任务列表

| 编号 | 任务 | 依赖 | 验收标准 |
| ---- | ---- | ---- | -------- |
| T1   | ...  | -    | ...      |
| T2   | ...  | T1   | ...      |

## 分阶段计划

### P0

- <首要里程碑内容>

### P1

- <后续阶段内容>
```

### checklist.md

```markdown
# <需求标题> - 检查清单

## 开发前

- [ ] 需求边界已确认
- [ ] 涉及文件/模块已定位

## 开发中

- [ ] <关键实现点>

## 完成后验收

- [ ] <对应 spec.md 中的验收标准逐条列出>
```

## 注意事项

- 三个文档内容保持一致：`tasks.md` 的任务应与 `spec.md` 的需求对应，`checklist.md` 的验收项应与 `spec.md` 的验收标准对应。
- 命名遵循现有约定：`<YYYY-M-D>-<slug>`，文档名固定为 `spec.md`、`tasks.md`、`checklist.md`。
- 不要创建需求之外的额外文档或目录。
