# 规则上下文按需加载优化

> 状态：已完成
> 日期：2026-08-24
> 代码区域：fullstack
> 目标仓库：`travel-ai/`

## 1. 背景与目标

当前工作区将多份项目治理规则作为常驻上下文注入。数据库迁移、环境安全、Spec 生命周期、服务清理和提交信息等专项要求会在不相关任务中重复出现，增加 Agent 每轮任务的上下文长度。

本需求将规则分为精简常驻层与按需专项层：保留所有任务都需要的安全和协作约束；将仅适用于数据库、环境变量、服务启动、功能实施和 Git 提交的详细规则改为场景化加载；同时使简单、低风险改动不再强制进入完整 Spec 生命周期。

## 2. 非目标

- 不删除数据库迁移、环境安全、验证门禁或服务清理的实质性约束。
- 不修改应用业务代码、数据库结构、环境变量或部署配置。
- 不改变已归档 Spec 的状态、内容或验收证据。
- 不为所有简单任务自动创建 Spec 文档。

## 3. 需求描述

### 用户故事 / 使用场景

- 作为项目协作者，我希望每次任务只获得与当前工作相关的规则，减少无关上下文。
- 作为维护者，我希望数据库、环境安全和验证要求在相关场景仍能完整生效。
- 作为开发者，我希望单文件修复、样式调整和文档小改动不被完整 Spec 流程阻塞。

### 功能需求

#### F1 精简常驻规则

- 建立一份短小的核心规则，只包含中文沟通、现有约定、保护用户已有改动、敏感信息保护、验证责任和未经要求不得提交等跨任务约束。
- 将常驻规则控制为指向专项规则的路由提示，不复制专项规则的完整内容。
- 统一 `AGENTS.md` 与核心规则的职责，避免重复描述相同的安全、验证和提交流程。

#### F2 专项规则场景化加载

- 数据库 schema 变更时加载数据库迁移规则。
- 新增、删除或修改环境变量和生产配置时加载环境安全规则。
- 启动服务或进行后端/API 验收时加载服务清理及验证门禁规则。
- 用户明确要求创建 Git commit 时加载提交信息规则。
- 仅在新增中大型功能、跨模块需求、公共 API 或数据库变更时加载完整 Spec 工作流及生命周期规则。

#### F3 简单任务轻量流程

- 定义可直接执行的低风险任务范围：单文件 Bug 修复、类型错误修复、文案或样式调整、针对性测试补充、局部文档和配置修改。
- 明确简单任务仍须遵守核心安全约束，并按变更风险执行必要验证。
- 不符合轻量范围或需求边界不清时，仍按完整 Spec 流程评审。

#### F4 加载配置与验证

- 检查并调整 Rule front matter 或工作区规则配置，确保仅核心规则为常驻加载，专项规则具有明确场景或按需加载方式。
- 提供规则加载矩阵，说明每份 Rule 的触发条件、常驻状态和职责。
- 使用代表性的简单任务和数据库任务进行静态核对，确认前者不加载无关专项规则，后者保留迁移要求。

## 5. 验收标准

- [x] 仅 `core.md` 被声明为常驻规则，且其内容仅覆盖跨任务的最小约束和专项规则路由提示。
- [x] 每份专项规则都具有可复核的触发场景或按需加载说明；实际加载器需按 front matter 解释该配置。
- [x] `AGENTS.md` 不再重复核心规则或专项规则中的完整内容，保留项目结构、命令和必要导航信息。
- [x] Spec 工作流明确区分完整 Spec 适用范围和可直接执行的简单任务范围。
- [x] 简单任务的轻量流程仍要求安全检查和与风险匹配的验证，不降低数据库、环境或 API 变更的治理要求。
- [x] 规则加载矩阵完整列出核心与专项规则的状态、触发条件和职责。
- [x] 通过静态检查确认简单任务不会要求读取无关的数据库或提交规则，数据库变更仍要求迁移规则。
- [x] 修改后的文档不包含真实密钥、用户数据或无关业务改动。
