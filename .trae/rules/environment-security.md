# 环境安全规范

环境变量和运行配置是应用契约的一部分。新增、删除或重命名配置时，必须同步代码、示例配置、文档和部署环境，并完成环境审计。

## 配置契约

- 新增、删除、重命名 `process.env.*` 或 `import.meta.env.*` 引用时，同步更新 `.env.example` 及相关配置说明。
- 为每个变量说明用途、是否必填、允许的格式或范围、适用环境和默认行为。
- 服务端密钥只能由服务端读取；不得通过客户端构建产物、接口响应或日志暴露。
- 不提交 `.env`、真实密钥、令牌、数据库密码或包含这些内容的构建产物。

## 生产配置

- 生产环境必须显式设置生产模式，不得依赖开发默认值。
- 生产 JWT 密钥必须为非空、非默认、非示例和不可预测的值；禁止使用占位文本或开发密钥。
- 生产 CORS 必须使用明确的允许来源，不得无条件允许任意来源并携带凭据。
- 请求体大小、外部模型请求超时和并发资源限制必须有明确边界，避免无界输入和长期占用。

## 敏感信息保护

- 日志、验收报告、错误追踪和监控指标不得输出 API Key、JWT、数据库密码或完整认证头。
- 错误响应只返回用户可处理的错误类别和必要上下文，不返回堆栈、内部路径、供应商凭据或完整上游响应。
- 用户对话、检索内容和模型响应按敏感数据处理；调试和报告只能使用摘要、计数、长度或脱敏片段。
- 记录请求时应过滤查询参数、请求头、请求体和响应体中的密钥及用户内容。

## 检查责任

涉及环境配置的变更必须检查：配置契约是否同步、生产安全值是否满足要求、CORS 是否收敛、请求体和外部调用是否有超时、错误暴露是否受控，以及日志和报告是否完成脱敏。
