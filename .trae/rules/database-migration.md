# 数据库迁移规范

数据库结构变更必须可追踪、可重复验证并具备回滚边界。应用启动初始化只负责安全的基础准备，不得隐式承载新的不可逆 schema 迁移。

## 变更记录

每次 schema 变更必须说明：

- 版本标识、执行顺序和适用数据库版本。
- 是否幂等，以及重复执行时的预期结果。
- 备份范围、备份完成条件和恢复验证方式。
- 升级步骤、兼容窗口、数据转换和回滚步骤。
- 对现有数据、索引、约束、性能和停机窗口的影响。

## 启动与迁移边界

- 禁止将新的不可逆建表、删表、删列、改类型或数据破坏操作隐式添加到应用启动初始化流程。
- 启动流程可以执行明确幂等且不会破坏已有数据的基础准备，但必须记录其边界。
- 需要版本顺序、备份或人工确认的变更必须作为独立迁移步骤执行，并在应用使用前完成。
- 破坏性变更优先采用扩展、迁移数据、切换读取、收缩的兼容流程，不能直接假设所有实例同时升级。

## 升级与回滚验证

变更完成后必须分别验证：

1. 空库从初始化状态到最新版本的完整升级。
2. 至少一个具有代表性的已有库从当前版本按顺序升级到最新版本。
3. 迁移重复执行的幂等性和失败后的重试行为。
4. 备份可恢复，回滚步骤可执行，回滚后应用和数据约束仍满足预期。

没有可执行回滚的破坏性变更必须在变更说明中明确标记不可逆、保留恢复方案并获得维护者确认。

## 数据生命周期

涉及用户删除、注销或数据清理时，必须说明主记录、会话、刷新令牌、关联数据和长期记忆的生命周期处理，避免遗留可继续使用的身份凭证或未授权的用户内容。
