# 验证门禁规范

代码变更在提交或交付前必须提供可复核的验证结果。验证范围按照变更类型扩展，未执行的项目必须明确说明原因。

## 默认验证

所有影响代码、配置、依赖或构建行为的变更，默认执行：

1. `npm run type-check`
2. `npm run build`

命令应在仓库根目录执行。若依赖未安装、环境变量缺失或外部服务不可用导致命令无法执行，应记录阻塞原因，不得将未执行视为通过。

## 变更类型与专项验证

| 变更类型 | 最低专项验证 |
| -------- | ------------ |
| API、路由或请求响应 | 启动服务后验证相关接口的成功、参数错误和鉴权边界；至少执行 `/api/heartbeat` 冒烟检查 |
| 鉴权、会话或令牌 | 验证未登录、有效身份、过期或无效令牌，以及跨用户访问边界 |
| SSE、流式响应或长连接 | 验证连接建立、事件顺序、正常结束、异常结束和客户端断开后的资源释放 |
| 数据库 schema、索引或初始化 | 读取并执行数据库迁移规则；按其中要求验证空库、已有库、幂等性、备份和回滚 |
| RAG、检索或评测 | 执行仓库已有的相关评测命令，说明数据集、外部模型和未覆盖场景 |
| 环境变量或生产配置 | 读取并执行环境安全规则，完成环境审计并检查示例配置、生产配置和敏感信息边界 |

专项验证不能替代默认的类型检查和构建，除非变更明确只涉及文档且不影响运行行为。

## 测试命令边界

- 未配置测试框架时，不得自行假定存在测试套件。
- 退出成功但只打印占位提示的测试脚本不构成测试通过证据。
- 测试命令不存在、测试为空或仅返回固定成功值时，应在报告中标记为“未提供有效测试”，并执行可用的类型检查、构建或专项验证。

## 结果汇报

验收摘要至少包含：

- 实际执行的命令及每条命令的退出码。
- 验证覆盖的变更类型和关键结果。
- 外部依赖、环境变量、服务或凭据限制，但不得包含凭据值。
- 未执行的检查、失败的检查及其原因。
- 若启动过服务，按服务关闭规则清理进程，并说明默认 `3300` 端口是否已释放。

报告、日志和错误信息必须脱敏，不得输出 API Key、JWT、数据库密码、完整用户对话或完整模型响应。
