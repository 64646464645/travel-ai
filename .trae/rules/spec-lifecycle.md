# Spec 生命周期规范

Spec 是需求、实现任务和验收证据的共同依据。每个 Spec 必须位于 `.trae/specs/<YYYY-M-D>/<area>/<slug>/`，并包含 `spec.md`、`tasks.md`、`checklist.md`。

## 状态机

允许使用以下状态：

| 状态 | 含义 | 可转换到 |
| ---- | ---- | -------- |
| 草案（待评审） | 需求尚未完成评审 | 已确认、废弃 |
| 已确认 | 范围、验收标准和任务已确认 | 实现中、废弃 |
| 实现中 | 已按任务开始修改代码或文档 | 已完成、阻塞、废弃 |
| 阻塞 | 受到明确的环境、依赖或决策阻塞 | 实现中、废弃 |
| 已完成 | 任务和验收清单均有证据支持 | - |
| 废弃 | 不再实施，需记录原因 | - |

状态变更必须在 `spec.md` 的状态行和变更记录中体现。阻塞和废弃必须说明原因；已完成必须记录验证命令、结果或其他可复核验收证据。

## 三份文档一致性

- `spec.md` 定义背景、边界、功能需求、涉及文件和验收标准。
- `tasks.md` 按 T1、T2 等编号拆分可执行任务，任务必须覆盖对应需求并声明依赖。
- `checklist.md` 必须覆盖开发前、开发中和完成后验收，且与 Spec 验收标准保持一致。
- 修改需求、文件范围或验收标准时，必须同步更新三份文档，并在 `spec.md` 变更记录中说明原因。

## 实现与验收

按 `tasks.md` 编号顺序执行任务。每完成一个任务，立即标记对应任务并记录必要的实现结果；不得只在全部完成后批量修改状态。编码完成后逐项执行 `checklist.md` 的完成后验收，未通过项必须修复或标记阻塞，不得将未执行项勾选为完成。

验收证据应包含命令、退出码、检查结果、接口状态或文档核对结果，并遵守敏感信息脱敏要求。证据不足时只能标记为待验收。

## 废弃与归档

废弃 Spec 保留原有三份文档和变更记录，状态改为“废弃”并注明原因、替代 Spec 或后续处理方式。不得删除历史验收证据，也不得复用已废弃目录承载新需求。
